# 复盘与盘中整合：实测与后续路线

本轮采用 FastAPI 新版作为服务底座，保留原系统的数据资产与“复盘→次日观察”的工作流程。原 Flask 8899 未改动，新增内容在独立本地测试库验收。

| 对比项 | 原 LocalStockAllInOne | 新版改造前 | 本轮整合 |
| --- | --- | --- | --- |
| 业务流程 | 竞价、盘中、复盘总控与历史仓库较丰富 | 页面分散，部分监控入口占位 | `/cockpit` 联动基准日涨停池与目标日行情 |
| 日期证据 | `data_contract.build_envelope` 以当前时间填 quoteTime；today 可升级为 tradeable | 快照仅保留采集时间 | 保存 upstream source_at；日期缺失、异常、过期、非交易时段、历史行情分开展示 |
| 数据不足 | 部分聚合以 0 代替缺失 | 缺多模块仍从 50 分起评分 | 缺关键模块或情绪分/资金值返回 null，旧报告读取和列表同步降级 |
| 历史利用 | 大型 SQLite 日线、分钟线、冷热分库 | 未接入旧库 | 可选只读日线查询，使用原索引，不复制全库、不远程请求 |
| 交易执行 | 需单独审计每个执行通道 | place_order 仅 INSERT 订单，页面称已提交 | 明示本地记录模式，无券商执行；账户列表不返回凭证 |

## 已完成的具体修复

- 强势池总数与行业分布使用全部已入库记录，展示样本仍只返回前 20 条。
- 历史情绪趋势增加 `trade_date <= requested_date`，避免未来日期混入历史分析。
- 情绪缺失字段使用 null，真实 0 分不再被替换为 50 分；恢复报告封板率字段。
- 快照 5xx/网络失败保留原始错误类别，不再被本地每分钟冷却伪装为 429。
- 清理旧快照时保留每日最后一批；这批不保证是收盘快照，应按源时间判断。
- 大额成交额 PostgreSQL SUM 返回 Decimal，修复市场概览除以浮点数造成的异常。
- 观察池仅取目标日期之前的最近已入库涨停日；可能有日期缺口，不假定为上一交易日。不在目标池不直接判定断板。
- 总控查看、过滤、历史日线查询只读本地数据。用户点击“采集今日行情”才拉上游快照；每分钟冷却沿用统一客户端。测试实例自动调度仍关闭。

## 旧数据接入

在本机私有环境配置 `LEGACY_MARKET_DB` 指向旧库 `market_cache.db`。默认不配置。只读取固定表 `stock_daily_kline`，按六位股票代码、截止日期查询最多 120 条。SQLite URI 使用 `mode=ro`，同时 `query_only=ON`；查询进度预算 2 秒，忙等待 1 秒，不占用异步事件循环。

历史接口不输出磁盘路径。来源沿用旧库 source；过滤无效日期、非有限价格及不满足 OHLC 基本关系的行，返回拒绝条数。复权口径、成交量单位和完整交易日覆盖尚未核验，因此仅展示 OHLC，不能直接用于新策略回测或实时决策。

## 建议下一阶段按此顺序推进

1. 建立按数据集/股票/日期/采集时段的持久化完成清单，区分“真实空池”和“未采集/接口失败”；当前空表仍保守显示缺失，避免假零。
2. 先统一旧库日线复权、金额和成交量单位，再统计交易日缺口。采用官方交易日历、按缺口补采并对照样本，禁止按自然日全量重拉。
3. 将盘后观察名单冻结，记录生成时间、依据和版本；次日行情只用于验证，不能回填到昨天的选股因子。当前名单由已有基准日池重算，尚不是不可变策略快照。
4. 竞价用带源时间的 9:25 截面，盘中全市场低频扫描、观察池更高频更新；当前新增总控以手动采集验收，尚未完成竞价信号全链路迁移。
5. 板块/资金先核验覆盖证券数量与数据单位，再接评分；现有少数个股资金不能代表全市场。规则分仍为旧启发式，不代表经回测验证的预测模型。
6. 券商连接、订单状态核对、撤单回报是独立交付，当前只做组合记账，未执行真实交易。

迁移新增可空 `market_snapshot.source_at`，不回填假时间。启动前执行 `alembic upgrade head`。旧服务无需停机；回退代码时新增列保留。
