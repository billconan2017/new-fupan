# 主策略的实时纸面执行

主策略 `close_auction_v1` 使用已有的固定规则，不根据这次历史结果调参：前晚涨停、强势、龙虎榜至少两项交集，成交额至少1亿元，普通沪深主板，按原规则排序最多5只、同一行业最多2只；次晨竞价涨幅1%至8%、完整规则分至少60，最多3只。`hot_auction_v1` 继续保留为热点并集对照。

## 自动时序

- 盘后定时采集完成后，冻结次日候选；没有完整证据不冻结。
- 09:26至09:29冻结当日竞价候选，不补造错过的竞价。
- 09:35、09:37、09:39优先运行 `paper_live`：首根完成5分钟K线收盘高于开盘才确认。未知可在窗口内重试，否决不可覆盖。
- 09:45以后在奇数分钟核验09:40开始的K线参考价、单一价格状态、涨跌停价和费用后可买股数。只记模拟入场，不下单。
- 10:00终结未完成确认。只有在09:40前已记录确认的信号可以产生模拟入场事件。
- 盘后定时评价T+1/2/3。实时入场用已冻结分钟和当日涨跌停证据，后续日线、退出日限制价另行获取。缺失、未到期、卖出受阻分别记录。

现有每分钟systemd计时器负责调度；偶数分钟留给行情、图表任务。长时间上游阻塞可能错过确认，此时明确记为错过，不能回补。网络返回后的实际观察时间决定是否仍在确认窗口，不能以请求开始时间倒签。

## 证据与统计

新增 `wb_paper_events`，以 `(signal_id, kind)` 唯一约束保存确认和入场；包含原始输入、规则版本、实际观察时间。重复执行不覆盖旧事件。迁移只增加表，部署前保留本地数据库备份。

实时与回溯共用 `confirmation_gate` 与 `evaluate`。主页主策略统计只纳入同时具有实时模拟入场事件和 `prospective_confirmed` 评估标识的成熟T+1样本；旧纸面观察总表保留盘后重建结果并标注来源。

没有券商订单接口。模拟参考价使用09:45结束K线的开盘价，不能证明09:40真实成交，平均单笔净变化也不是账户收益。

## 历史重建

运行 `.venv/bin/python scripts/replay_recent.py --sessions 10 --universe close`。复用历史接口缓存，以相同的 `preparation_rows`、`close_picks`、`choose_candidates` 和入场/退出判断重建；输出本地 `data/research/primary_replay.json`，不提交原始数据。盘后原始公布时点并未全部核验，部分接口日期只由请求参数约束，不能当作历史实时荐股。

本次2026-09-03至09-16：5个候选，2个未入场，1个模拟入场，2个数据待核验。没有具备完整退出核验的成熟样本，不报告有效胜率或最优持有期。
